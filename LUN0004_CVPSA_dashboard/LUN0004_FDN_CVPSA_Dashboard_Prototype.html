Glossary and Guide

How to Read the Dashboard

  • Sensor Health Overview → "Can I trust this data now?"
  • PSD KPI Trends → "What size is the material?"
  • PSD Period Comparison → "Has the size, and the oxidation classification, changed between two periods?"
  • Ore Oxidation Analysis → "What share of the visible ore surface is classified as oxidised, and how does that line up with size?"
  • Foreign Object Detection → "When did the detector flag anomalies, and how large were they?"
  • Reporting Time: All times are site local (UTC-05:00).
  • Filters: The Global Date Range Filter (Last 7 days) applies to the whole dashboard except the Period A and Period B selectors on page 3. FDN has one sensor: lun_fdn_cvpsa_6140_cvy_0001.
  • Missing data: a gap, empty bar, hatched cell or "null" means no reading. Missing data is never shown as zero.
Sensor Health Overview

Latest Sensor Health Status

Snapshot of the latest reading. Not bound to the date range filter.

  • Latest reporting time: timestamp of the newest reading, in site local time.
  • Camera Comms: camera online and receiving frames.
  • Run Signal OK: belt run signal on.
  • State All OK: sensor operations are normal and no faults reported.
  • Image Health OK: image passed all quality checks.
  • OPC Heartbeat: the sensor's heartbeat counter is still increasing.
  • PSD / Oxidation / FOD Reporting: that output produced a value recently.
  • Last Reported: time of the most recent reading.

A null flag means the sensor did not report that value on its last reading.

Sensor Health and Comms States

Per local day across the selected date range.

  • Sensor Healthy: fraction of time the camera was online and the image passed all quality checks (not blurry, dark, noisy or stationary).
  • Sensor Unhealthy: fraction of time with a camera comms fault or an image fault, split by cause in the second chart.
  • Data Time Coverage: received samples as a share of expected samples. Low coverage means averages for that day rest on less data.
  • Measurement Output Availability: share of healthy time in which PSD, oxidation and FOD each reported.

Sensor Healthy does not consider the belt run signal. A stopped but clean sensor still reads as healthy.

PSD KPI Trends and Period Comparison

PSD Metrics

Particle size distribution over the selected date range. Each metric has a trend (over time) and a distribution (how often each value occurred).

  • P20 (mm): size below which 20% of material passes. The fine end.
  • P50 (mm): median size. Half the material is finer, half coarser.
  • P80 (mm): size below which 80% of material passes. The standard size indicator.
  • Top Size (mm): the largest particle width measured. The coarse end.

S-Curve (Cumulative Passing): cumulative percent passing against particle size, one curve per complete local day.

Comparing Two Periods

Select two date ranges and a PSD metric.

  • Counters: the Period B (recent) value with its change versus Period A (baseline). An up arrow means Period B is higher.
  • Distribution Comparison: each period normalised to its own sample count, so periods of different length compare by shape.
  • Oxidation over the same periods: qualified means of OHF + OLF, OHF and OLF for the same Period A and B. Check qualified coverage for both periods before reading a difference.

Note: page 3 uses its own Period A and Period B selectors. The Global Date Range Filter does not drive these charts.

Ore Oxidation Analysis

Oxidation Fractions

Outputs of the CVPSA ore-colour classifier, per sample, each between 0 and 1.

  • OHF and OLF: fractions of the visible ore surface assigned to the two oxidised colour classes.
  • OHF + OLF: the apparent oxidised fraction. The headline oxidation measure on this dashboard.
  • ONF and OOF: fractions assigned to the two remaining classes. Shown for context.
  • OOCF: ore-coverage qualification value. Samples with OOCF below 0.3 are excluded from every oxidation average.

What these are not: colour classifications of the visible ore surface. They are not laboratory oxidation assays and do not measure oxidation inside particles. Agreement with assays must be established separately.

Reading the Oxidation Charts

  • Qualified: sample with OOCF ≥ 0.3 taken while the sensor was healthy. Only qualified samples enter averages.
  • Excluded: sample received but not used (OOCF below 0.3, or sensor unhealthy). Shown in the Sample Status chart, the heatmap (grey) and the hourly table.
  • No data: no sample received. Shown hatched or as a gap.
  • Daily and hourly values are means of qualified samples in that day or hour. Check Qualified coverage before comparing days.
  • Oxidation in PSD context: panels share one time axis so changes can be compared with P80 and Top Size of the same material. Lining up in time is not evidence that one causes the other.
  • Representative imagery: camera frames from the selected hour with the values recorded at each frame.
Foreign Object Detection

FOD Measurements

The detector reports per frame. This page does not define FOD events.

  • Anomaly detections: number of anomalies the detector found in a frame.
  • Max anomaly size (mm): size of the largest anomaly in that frame.
  • Detection frame: a reported frame with at least one anomaly detection.
  • Detection Frames (%): detection frames as a share of healthy reported frames.

Reading the FOD Charts

  • One object can appear in several consecutive frames, so detection frames do not equal objects.
  • Trends use the per-minute maximum, never the sum.
  • A detection is a detector output, not a confirmed foreign object.
  • No data means no frames were reported; zero detection frames means frames were reported without anomalies.

Missing inputs to populate with LUN0004 data
  1. Oxidation output schema. Exact tag or column names for OHF, OLF, ONF, OOF and OOCF, the Databricks table they land in, output cadence, and the date oxidation output began at FDN.
  2. OOCF rule. Confirm qualification is OOCF ≥ 0.3 (not >), and whether any other exclusion applies (empty belt, run signal, image health).
  3. Class definitions for OHF, OLF, ONF and OOF from the oxidation model documentation, and whether the four fractions are expected to sum to 1. Needed for glossary wording and a data-integrity check.
  4. Historised data check. Confirmation of which documented tags are actually historised for lun_fdn_cvpsa_6140_cvy_0001, from what date, at what rate.
  5. Camera comms and run signal tags at FDN (V2-only in the tag list). Without them, page 1 loses the Comms Lost split and the Run Signal column.
  6. Expected sample cadence per output, to compute coverage and to separate "no data" from "excluded".
  7. Image access. Frame storage location, timestamp key matching the measurement records, retention period, and whether Databricks can serve thumbnails.
  8. FOD event definition (detection/size threshold, merge gap, belt speed or frame rate) if event-based reporting is wanted. Until then page 5 stays frame-based.
  9. Minimum coverage rule for showing an hourly or daily oxidation mean (for example 50% qualified), and the minimum sample count before any scatter statistics are shown.
