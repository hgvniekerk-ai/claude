# 02-validate: check the register

One job: run the deterministic checks on the register and explain each finding in plain terms.

## Inputs

| Source | File/Location | Section/Scope | Why |
|--------|--------------|---------------|-----|
| Register | `projects/<slug>/work/network-01-register.md` | Full file | The data to check |
| Validator | `python3 tools/pe.py netcheck <register> --out <output>` | Command | Subnet, IP, duplicate, flow and NTP checks |
| Windows ports | `knowledge/network/net-windows-ports.md` | Full file, only if RPC or DCOM flows exist | Explain wide port ranges |

Do NOT load: evidence files, other projects. The validator is the authority on arithmetic; do not re-derive subnets by reasoning.

## Process

1. Run `python3 tools/pe.py netcheck projects/<slug>/work/network-01-register.md --out projects/<slug>/work/network-02-validation.md`.
2. Read the output. For each ERROR, say which register row to fix and why.
3. For each WARNING, say whether it is likely acceptable and what would close it.
4. Do not edit the register yourself unless the PE asks. The register is the PE's edit surface.

## Checkpoints

| After Step | Agent Presents | Human Decides |
|------------|---------------|---------------|
| 3 | Errors and warnings with proposed fixes | Fix the register and re-run, or accept warnings |

## Outputs

| Artifact | Location | Format |
|----------|----------|--------|
| Validation report | `projects/<slug>/work/network-02-validation.md` | Generated by `pe.py netcheck`: result, errors, warnings, conduit summary |
